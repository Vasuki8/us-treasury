# Selected official GDP publication history

Reviewed October 22, 2026. This is a deliberately small archive of **three official estimates for 2026Q1 real GDP**, separate from Meridian's immutable local retrieval vintages and its latest revised time series. It is not a reconstructed full NIPA database, an intraday availability record, or a claim that the third estimate is permanently final.

## Official source and exact selection

The [June 25 GDP release](https://www.bea.gov/news/2026/gdp-third-estimate-industries-corporate-profits-state-gdp-and-state-personal-income-1st) directly links the dated [GDP/GDI vintage-history workbook](https://www.bea.gov/sites/default/files/2026-06/gdp-gdi-vintage-history.xlsx). A credential-free GET succeeded on the review date. Its `Vintage History` sheet explicitly describes estimates by publication/vintage date, organized by estimate quarter, with historical quarters extending to 2002Q1. Only the three GDP rows in the 2026Q1 section are admitted here; the workbook's other quarters, current-dollar levels and GDI columns are excluded.

Values are **percent change from the preceding quarter, seasonally adjusted and annualized**, matching the existing GDP source identifier `A191RL`, NIPA Table 1.1.1 line 1. The release summaries explicitly label their comparison table `Percent change (SAAR) from 2025:Q4 to 2026:Q1`. The collector neither reannualizes the numbers nor substitutes the workbook's GDP current-dollar level or GDI measure. `period='2026-01-01'` is a quarter reference, not a publication date.

All three release documents specify an 8:30 a.m. EDT release embargo. That corroborates the dated releases; it does **not** demonstrate the actual instant at which a server made the results public. Archive records consequently retain `publicationDate` at day precision and `publishedAt:null`. They do not backdate a retrieval to the embargo, a calendar schedule, an Excel modification property, or an HTTP Last-Modified value. The release pages now mark their figures as superseded and warn that interactive-table links show the latest data; those current interactive tables are not historical-vintage inputs.

The review probe read 74,168 workbook bytes, SHA256 `d12fb3a5b4d9184a9288d18eb249ea14683ac2614231b018c9f02a28d3c22b73`. A subsequent successful collector probe had actual retrieval time `2026-10-22T16:06:22.618Z` and the same hash. These facts describe the bytes obtained on this review date. They are not a cryptographic claim about bytes served in April, May or June. A later official correction must be handled as new evidence rather than silently rewriting an admitted record.

## Scope, rights and exported meaning

BEA's [copyright FAQ](https://www.bea.gov/help/faq/147) places website information in the public domain unless stated otherwise and permits use/reproduction without specific permission. No contrary notice was found on the reviewed BEA-authored statistical workbook or three releases. Commercial display of the selected factual statistics and CSV redistribution therefore fit the existing scoped BEA reuse basis. Retain `Source: U.S. Bureau of Economic Analysis.`, the exact original workbook title, original source code, quarter, estimate stage, publication date, actual access date, links, and source value/cell references. BEA's [citation guidelines](https://www.bea.gov/help/guidelines-for-citing-bea) specifically recommend identifying an estimate's vintage. Do not imply BEA endorsement or redistribute unrelated logos, photographs or third-party material under this admission.

`scripts/publication-policy.mjs` independently admits only this exact workbook URL and these three release/quarter/stage/date combinations. It is not a hostname-wide expansion of the latest-data allowlist. `assertPublicationData` accepts an empty initial archive or the complete three-record sample, rejects unreviewed fields, wrong identifiers/units/rights/source cells, duplicate records, nonfinite values, invented publication instants and invalid provenance. Integration must invoke this admission before writing or building the static archive. The archive is not included in source freshness or required-daily publication checks.

## Collector contract and verification

`collectPublications({fetchImpl})` performs one bounded GET of the exact workbook, hashes the actual response bytes and records actual retrieval metadata. It returns `{version:1,releases:[...]}`. `parseGdpPublicationWorkbook(bytes,{provenance})` provides deterministic parsing without network or data writes. Each release includes stable ID, `seriesId`, `period`, `estimate`, `publicationDate`, date precision, value/native units, `sourceValue`, original date text, four original worksheet-cell references, release-evidence URL and full workbook retrieval provenance. Workbook source cells are retained even when the displayed numeric value omits the source's trailing decimal zero.

The parser uses the existing bounded ZIP reader and a small in-memory XML reader, with explicit workbook/sheet/relationship namespaces, the `Vintage History` sheet relationship, reviewed title, quarter, measure/unit/estimate headers, exact selected rows and dates. It reads shared strings or whole-day dates in Excel's 1900 date system, rejects the fictitious 1900 leap date, fractional dates and the unreviewed 1904 system. Dates in this actual workbook are shared text strings; the advance date's `GDI not published` annotation is retained and cannot make GDI a GDP observation. Formula cells, external worksheet relationships, duplicates, malformed XML, declarations/entities, missing estimates, schema drift and redirects fail closed. No third-party spreadsheet dependency or new service is used.

Focused tests cover successful text/numeric date decoding, original source values/cells, unknown publication time, structural/numeric/schema failures, comments, redirects, HTTP failure, precise source/rights admission and actual response hashing. A separate live read-only probe successfully parsed the actual official workbook. No canonical snapshot, local retrieval history or static archive was written during these checks.
