# Browser research storage

Normal research workspaces and frozen packages use native IndexedDB database `meridian.research-library.v2`, version 1, object store `records`. Each validated record is stored independently, with a random revision used by an atomic compare/write transaction. Complete SOFR history can therefore exceed the former shared 3 MiB localStorage envelope without making unrelated small saves fail. Existing package validation, SHA-256 integrity checks, the 12 MiB package bound and the 50 workspace/20 package limits remain in force.

`createResearchLibrary(storage, options)` keeps its existing asynchronous save, pin, remove and list methods. Its action results retain `ok`, `persisted`, `reason` and, for saves/pins, `record`. `persisted: true` means the transaction completed, not merely that a database request succeeded. IndexedDB provides cross-tab serialization without Web Locks. Distinct records can save independently; a stale edit or deletion of the same record returns `reason: 'conflict'` and preserves the latest committed record. The stale local evidence remains available for JSON export. Reload before deliberately replacing a newer record.

`getState()` adds `backend` (`indexeddb`, `localstorage` or `session`) and `durability.workspaces[id]` / `durability.packages[id]`, each containing `{status, reason}`. `durable` identifies a committed record; `session` identifies a quota/limit/locking fallback; `failed` identifies an unavailable, conflicted or invalid-record write. A failed edit remains in memory and exportable. A failed deletion keeps the visible record. Aggregate `sessionOnly` is true when any current change is not committed, but does not make future unrelated saves session-only. A successful save of one record does not change another record's status.

The old `meridian.research-library.v1` localStorage bytes are never removed during migration. A valid legacy envelope is validated before import; each record migrates in its own transaction and retries on a later opening if its transaction fails. A committed deletion leaves a small revisioned tombstone, preventing stale tabs or the retained legacy envelope from resurrecting deleted evidence. A preexisting database record takes precedence over its legacy copy. Malformed legacy bytes and invalid database records are preserved for recovery and are never silently repaired, overwritten or deleted. An invalid record does not prevent other valid database records from opening or saving.

If a browser has no IndexedDB API, the previous localStorage format remains usable under an exclusive Web Lock. Its 3 MiB cap still applies, but a save serializes committed records plus only its target, so an oversized session package no longer poisons later small saves. Missing/rejected locks leave edits in session. When IndexedDB exists but cannot open (including blocked upgrades, access errors or a four-second timeout), legacy records remain readable and new edits stay in session: the application avoids creating a second writable authority that could hide newer database records. A late successful open after timeout is closed; schema version changes also close the old connection.

Browser storage is local to the origin and browser profile. Clearing site data, private browsing, browser eviction, disk loss or device changes can remove it. Downloaded pinned JSON is the portable recovery copy; its checksum proves integrity, not publisher identity. No account, external service or new dependency is involved.

The Node regression suite uses a transaction-level database double because Node has no IndexedDB API. It covers full-history reload/export, per-record quota isolation, aborts after request success, cross-tab conflicts, migration retry, tombstones, invalid-record preservation, blocked/denied opens and unavailable Web Locks/localStorage. Real browser acceptance should also exercise native IndexedDB pin/reload/export.
