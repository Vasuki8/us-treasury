# Portable settings and research questions

Preferences retain the existing `saved` active-watchlist alias and add up to 20 named watchlists, each with an ID, name and ordered series IDs. Legacy preferences migrate to `default` / “My watchlist” without changing their order. Switching lists restores that list's order; ordinary save, remove and move actions update the active list. Deleting a list requires another list to remain. Named-list records and appearance preferences stay separate from immutable frozen packages.

Settings JSON uses schema `meridian.research-settings`, version 1, and a 1 MiB limit. It includes validated display preferences, named watchlists and up to 50 saved view configurations. It cannot contain package observations, frozen CSVs, credentials or executable values. Export/import controls are available in both Watchlist and Saved views. Frozen packages use their existing separate JSON import/export.

`exportResearchSettings({preferences,workspaces})` returns canonical JSON. `importResearchSettings(text)` validates the complete file before returning `{version,preferences,workspaces}`. `mergeResearchSettings(currentPreferences, imported, currentWorkspaces)` preflights combined limits and returns `{preferences,workspaces}`: the returned workspaces are only additions to save. Existing lists and views are preserved. Identical records with the same ID are skipped; different records sharing an ID receive fresh local IDs. Imported active-list selection follows its copied list, while imported appearance and sort preferences apply. No merge helper writes storage itself.

Saved-view summaries describe controls relevant to their page: a curve's overlay dates, auction filter and selected ID, refinancing horizon and hypothetical shock, economic family or section, publication cutoff or retrieval-history cutoff. They do not summarize unrelated default comparison IDs.

A saved workspace may include an optional version-1 `researchQuestion`: hypothesis, supporting and contradicting series IDs, frozen baseline package ID, review date/event and native-value conditions. Existing workspaces without a question remain valid. The editor uses explicit labels and freezes a baseline when saved through the controller. A saved question's baseline refers to a package; transferring settings alone does not transfer that package. A missing baseline is shown as unavailable.

`evaluateResearchQuestion(question,{catalog,baselinePackage,events,now})` compares the retained frozen baseline with the latest captured catalog. It separately reports newly available reference periods, observed changes for the same period, historical backfills and changed measurement metadata. An observed same-period difference does not establish a verified agency revision, publication time or cause. Missing series are not substituted, and changed units/frequency/adjustment/measurement identity make numeric comparisons unavailable.

Each condition reports the threshold in native units, current value/date/status, frozen baseline value/date/status and whether the condition was entered or left. A crossing is unavailable when either reading is missing or measurement metadata changed. Review timing uses the requested calendar date or retained schedule-event date; it does not establish that a scheduled publication occurred. Supporting/contradicting roles remain the researcher's labels. No hypothesis score, forecast, background notification or investment instruction is generated.
